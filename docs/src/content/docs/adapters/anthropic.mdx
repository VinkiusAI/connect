---
title: Anthropic Adapter
description: Convert capabilities to Messages tool definitions and dispatch tool_use blocks.
---

Use this adapter when your application exchanges Messages-style tool definitions and receives `tool_use` blocks. Conversion and execution are separate operations.

## Convert and dispatch

This example constructs only the structural block read by the dispatcher; it does not depend on an external client API.

```typescript
import { Vinkius } from '@vinkius/connect';
import { runAnthropicToolUse, toAnthropicTools, type AnthropicToolUse } from '@vinkius/connect/anthropic';

const vinkius = new Vinkius({
  appId: 'vk_app_replace_me',
  apiKey: 'vk_app_sk_replace_me',
});
const capabilities = await vinkius.user('user_123').capabilities();
const tools = toAnthropicTools(capabilities);

const firstTool = tools[0];
if (firstTool) {
  const returnedUse: AnthropicToolUse = {
    name: firstTool.name,
    input: {},
  };

  const result = await runAnthropicToolUse(capabilities, returnedUse);
  console.log(result.content, result.isError);
}
```

Pass `tools` to the operation in your installed client that accepts this shape. After execution, your application is responsible for converting `CapabilityResult` into the response block expected by its conversation loop.

## Converted format

`toAnthropicTools` returns one entry per capability:

```typescript
{
  name: capability.name,
  description: capability.description,
  input_schema: capability.inputSchema,
}
```

A schema is kept only when it is a non-empty object; otherwise `input_schema` becomes `{ type: 'object', properties: {} }`. No schema validation or rewriting is performed.

The adapter has no runtime dependency on an Anthropic package. Its exports describe a structural subset. Confirm that subset against the external SDK version installed by your application.

## Naming and dispatch

`runAnthropicToolUse` matches `use.name` against the capability display name. It does not match `rawName`. Display names default to `${connector}__${rawName}`.

The first capability with a matching display name is executed, so duplicate display names are order-dependent. Use the same capability array for conversion and dispatch.

A nullish `input` value observed at runtime becomes `{}`. The adapter otherwise passes the input object through without validation or coercion.

An unknown name throws a plain `Error("Unknown capability: …")`.

## Results and limits

The dispatcher preserves the complete `CapabilityResult`, including every content part and `isError`:

```typescript
const result = await runAnthropicToolUse(capabilities, returnedUse);

if (result.isError) {
  // The capability completed with an error result.
}
```

A returned `isError: true` is not thrown. Exceptions from capability execution still reject the promise.

The helper does not create a provider response block and does not continue the model loop. It also does not accept `ExecuteOptions` or an `idempotencyKey`; call the matching `Capability` directly when those options are required.

## Public API

The `@vinkius/connect/anthropic` subpath exports:

```typescript
interface AnthropicTool {
  name: string;
  description: string;
  input_schema: JSONSchema;
}

interface AnthropicToolUse {
  name: string;
  input: Record<string, unknown>;
}

function toAnthropicTools(capabilities: readonly Capability[]): AnthropicTool[];

function runAnthropicToolUse(
  capabilities: readonly Capability[],
  use: AnthropicToolUse,
): Promise<CapabilityResult>;
```
